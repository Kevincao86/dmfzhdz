# 分销员申请 · 实名认证接口设计

**方案代号：** `distribution_kyc_v1`  
**版本：** 2026-07-14  
**关联：** [分销体系实现设计 v2](./分销体系实现设计-个人与服务商.md) · [分销员提现接入设计](./分销员提现接入设计.md)  
**适用范围：** 个人分销员申请（cs / dr / 星选小程序）；服务商分销员由 fws 总代创建，可选同样走 KYC

---

## 一、能否实现？结论先行

| 落地端 | 实名方式 | 可实现性 | 前提条件 |
|--------|----------|----------|----------|
| **微信小程序**（灵祺星选 MP） | **仅微信** | ✅ 推荐 | 小程序开通「城市服务实名校验」或「人脸核身」能力 |
| **cs / dr Web（微信内打开）** | 微信 | ✅ | 同上；H5 可跳小程序或使用 JS-SDK 相关能力 |
| **cs / dr Web（支付宝内打开）** | 支付宝 | ✅ | 支付宝开放平台签约「身份验证」产品 |
| **cs / dr Web（抖音内打开）** | 抖音 | ⚠️ 受限 | 主要为备案/小游戏 `tt.authenticateRealName`，通用分销 KYC 需向抖音申请能力 |
| **cs / dr 普通浏览器** | 微信/支付宝二选一 | ✅ | 引导「在微信/支付宝中打开」或使用人脸核身（微信） |

**总结：可以实现。** 微信小程序板块 **只接微信实名**（不对接支付宝/抖音）。cs/dr Web 按用户环境 **三选一** 引导；抖音能力作为补充，首期可 **仅微信 + 支付宝** 上线。

---

## 二、总体流程

```
分销员填写姓名+身份证号
        │
        ▼
按 landing_surface 选择 KYC 渠道
        │
   ┌────┼────┬────────────┐
   ▼    ▼    ▼            ▼
 微信  支付宝  抖音(可选)   拒绝/重试
   │    │    │
   ▼    ▼    ▼
平台服务端调用官方「校验/查询」接口
        │
        ▼
verification_status = passed → 允许提交分销员申请
        │
        ▼
运营台审核（KYC 已通过仍须人工审）
```

**安全原则：**

- 身份证号 **不落库明文**，仅存 `cred_id_hash`（SHA256）+ 脱敏 `cred_id_mask`（如 `3303**********1234`）
- 姓名可存；官方 `code` / `verify_id` / `certify_id` **一次性使用**，校验后立即丢弃
- 所有官方接口 **仅服务端调用**

## 三、微信小程序 · 仅微信实名（推荐方案）

> **约束：** 灵祺达人撮合小程序（星选）分销员申请 **只实现本节**，不调用支付宝/抖音 SDK。

### 3.1 方案 A · 城市服务实名校验（与微信支付预留信息比对）

**适用：** 分销员已绑定微信、且微信支付账户有预留实名信息。  
**官方文档：** [城市服务实名信息校验](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/cityservice/cityservice-checkrealnameinfo.html)

#### 3.1.1 小程序端：跳转授权页获取 code

```javascript
// 用户点击「微信实名认证」后
wx.navigateToMiniProgram({
  appId: 'wx308bd2aeb83d3345',
  path: 'subPages/city/wxpay-auth/main',
  extraData: {
    // 业务自定义，回跳时原样带回（可选）
    biz: 'distribution_kyc',
  },
  success(res) {
    // 用户取消或完成会在 onShow / App.onShow 处理 extraData
  },
})
```

**回跳处理（业务小程序 `app.js` 或申请页）：**

```javascript
// 从微信城市服务小程序返回
onShow(options) {
  const code = options?.referrerInfo?.extraData?.code
  if (code) {
    this.submitWechatRealnameCode(code)
  }
}
```

#### 3.1.2 服务端 · 校验实名信息（查询接口）

| 项 | 内容 |
|----|------|
| **接口名** | `checkrealnameinfo` |
| **URL** | `POST https://api.weixin.qq.com/intp/realname/checkrealnameinfo?access_token=ACCESS_TOKEN` |
| **调用方** | 灵祺 auth-api（轻量），**禁止小程序直连** |

**请求体：**

```json
{
  "openid": "用户在灵祺星选小程序下的 openid",
  "real_name": "张三",
  "cred_id": "330381199001011234",
  "cred_type": "1",
  "code": "城市服务授权页回跳的 code"
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| openid | 是 | 与当前小程序 appid 一致上下文下的用户 openid |
| real_name | 是 | 用户填写的姓名 |
| cred_id | 是 | 18 位身份证号 |
| cred_type | 是 | 固定 `"1"`（身份证） |
| code | 是 | 授权页返回，**一次性**，约 5 分钟内有效 |

**响应体：**

```json
{
  "errcode": 0,
  "errmsg": "ok",
  "verify_openid": "V_OP_NM_MA",
  "verify_real_name": "V_NM_ID_MA"
}
```

**判定为通过：**

```
errcode === 0
&& verify_openid === 'V_OP_NM_MA'
&& verify_real_name === 'V_NM_ID_MA'
```

| verify_openid | 含义 |
|---------------|------|
| `V_OP_NA` | 用户暂未在微信侧实名 |
| `V_OP_NM_MA` | 微信用户与填写姓名匹配 |
| `V_OP_NM_UM` | 微信用户与填写姓名不匹配 |

| verify_real_name | 含义 |
|------------------|------|
| `V_NM_ID_MA` | 姓名与身份证号匹配 |
| `V_NM_ID_UM` | 姓名与身份证号不匹配 |

**常见错误码：**

| errcode | 说明 |
|---------|------|
| 80111 | 实名校验 code 不存在或已用过 |
| 80113 | 无效 code |
| 1005 | appid 无效 / 未开通能力 |

**开通要求：** 需在小程序后台申请 **城市服务 · 实名信息校验** 权限（与政务/特定行业开放范围相关，提交业务说明：分销员 KYC、反洗钱）。

### 3.2 方案 B · 微信人脸核身 2.0（更强，可选升级）

**适用：** 城市服务权限难申请，或需「本人操作」防冒用。  
**文档：** [人脸核身 2.0](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/cityservice/FacialRecognitionVerify.html)

#### 流程三步

```
1. POST getVerifyId（服务端）→ verify_id
2. wx.requestFacialVerify({ verifyId })（小程序端，用户刷脸）
3. POST queryVerifyInfo（服务端，查询真实结果）← 必须调用
```

#### 3.2.1 获取 verifyId

| 项 | 内容 |
|----|------|
| **URL** | `POST https://api.weixin.qq.com/cityservice/face/identify/getverifyid?access_token=ACCESS_TOKEN` |

**请求体：**

```json
{
  "out_seq_no": "DIST-KYC-20260714-000001",
  "openid": "oXXXX",
  "cert_info": {
    "cert_type": "IDENTITY_CARD",
    "cert_name": "张三",
    "cert_no": "330381199001011234"
  }
}
```

**响应：**

```json
{
  "errcode": 0,
  "errmsg": "ok",
  "verify_id": "xxx",
  "expires_in": 3600
}
```

#### 3.2.2 小程序端刷脸

```javascript
wx.requestFacialVerify({
  verifyId: verifyIdFromServer,
  success() {
    // 仅表示 SDK 流程结束，必须以服务端 query 为准
    pollQueryVerifyResult(verifyId)
  },
})
```

#### 3.2.3 查询人脸核身结果（查询接口 · 必调）

| 项 | 内容 |
|----|------|
| **URL** | `POST https://api.weixin.qq.com/cityservice/face/identify/queryverifyinfo?access_token=ACCESS_TOKEN` |
| **文档** | [queryVerifyInfo](https://developers.weixin.qq.com/miniprogram/dev/server/API/face/api_queryverifyinfo.html) |

**请求体：**

```json
{
  "verify_id": "getVerifyId 返回",
  "out_seq_no": "与 getVerifyId 一致",
  "openid": "与 getVerifyId 一致",
  "cert_hash": "见官方 SHA256 规则"
}
```

**`cert_hash` 计算（官方规则）：**

1. 对 `cert_type`、`cert_name`、`cert_no` 分别标准 Base64（UTF-8）
2. 拼接：`cert_type=xxx&cert_name=xxx&cert_no=xxx`
3. SHA256 → 十六进制小写

**判定通过：**

```
errcode === 0 && verify_ret === 10000
```

**注意：** `verify_id` 有效期约 **1 小时**；`out_seq_no` 5～32 字符，同 appid 唯一。

### 3.3 微信小程序 · 灵祺封装 API

分销员申请页 **只调以下接口**，不直连微信：

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/meoo-distribution-kyc-wechat-init` | 入参：姓名、身份证号；返：`mode`（`cityservice` \| `face`）、跳转参数或 `verify_id` |
| POST | `/api/meoo-distribution-kyc-wechat-verify` | 入参：`code`（方案 A）或 `verify_id`（方案 B）；返：`passed`、`verifyToken` |
| POST | `/api/meoo-distribution-affiliate-apply` | 入参：...+ `kycVerifyToken`（5 分钟内有效的一次性令牌） |

**`kycVerifyToken`：** 服务端签发 JWT/HMAC，含 `openid`、`cred_id_hash`、过期时间，防止绕过 KYC 直接申请。

## 四、cs / dr Web · 支付宝实名

**适用：** 用户在支付宝 App 内打开 cs/dr 推广伙伴页，或 H5 唤起支付宝。  
**文档：** [支付宝实名认证](https://opendocs.alipay.com/open/0bk0tu)

### 4.1 方案 A · 身份证二要素核验（仅校验姓名+证号，无刷脸）

| 项 | 内容 |
|----|------|
| **method** | `datadigital.fincloud.generalsaas.twometa.check` |
| **文档** | [身份证二要素核验](https://opendocs.alipay.com/open/10c536f6_datadigital.fincloud.generalsaas.twometa.check) |
| **网关** | `POST https://openapi.alipay.com/gateway.do` |

**biz_content：**

```json
{
  "outer_biz_no": "DIST-KYC-20260714-000002",
  "cert_name": "张三",
  "cert_no": "330381199001011234",
  "cert_type": "IDENTITY_CARD"
}
```

**关键响应字段：**

| 字段 | 说明 |
|------|------|
| `match` | `T` = 姓名与证号匹配；`F` = 不匹配 |
| `certify_id` | 认证单据号（可存档审计） |

**判定通过：** 业务响应 `match === 'T'` 且无业务错误码。

**限制：** 不验证「是否为当前支付宝账号本人」，仅验证证号真实性。分销场景建议与 **支付宝账号 uid** 绑定记录。

---

### 4.2 方案 B · 支付宝实人认证（刷脸，推荐 Web 主方案）

| 步骤 | 接口 method | 说明 |
|------|-------------|------|
| 1 初始化 | `alipay.user.certify.open.initialize` | 获 `certify_id` |
| 2 开始认证 | `alipay.user.certify.open.certify` | 获认证 URL，唤起支付宝 App |
| 3 **查询结果** | `alipay.user.certify.open.query` | **必调**，确认最终状态 |

**文档：**

- [身份认证初始化](https://opendocs.alipay.com/open/02ahjy)
- [服务端 SDK 接入流程](https://opendocs.alipay.com/open/01brh4)

#### 4.2.3 查询身份认证结果（查询接口）

| 项 | 内容 |
|----|------|
| **method** | `alipay.user.certify.open.query` |
| **入参** | `certify_id`（初始化接口返回） |

**判定通过（典型）：** 响应中认证状态为 **成功**（以支付宝文档 `passed` / 状态枚举为准，接入时以 SDK 返回字段为准）。

**H5 唤起示例：**

```
alipays://platformapi/startapp?appId=20000067&url={encodeURIComponent(certifyUrl)}
```

## 五、cs / dr Web · 微信实名（非小程序）

用户在 **微信内打开 H5** 时：

| 方式 | 说明 |
|------|------|
| **推荐** | H5 引导跳转 **星选小程序** 同一套 KYC（§3），完成后带 `kycVerifyToken` 回 H5 |
| **备选** | 微信 JS-SDK + 城市服务（能力同 §3.1，需公众号/小程序关联） |

**不对 H5 单独接支付宝/抖音混用：** 微信环境只走微信 KYC。

## 六、抖音 · 实名（可选，首期可不上）

**文档：** [tt.authenticateRealName](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/api/open-capacity/user-information/info/authenticate-real-name)

| 项 | 内容 |
|----|------|
| **端** | 抖音小程序 / 小游戏 |
| **API** | `tt.authenticateRealName({ success, fail })` |
| **前提** | 用户已 `tt.login`；**必须由用户点击触发** |
| **回调** | `success` 仅表示客户端流程完成，**无服务端查询接口文档公开** |

**限制：**

- 公开文档以 **小游戏/备案** 场景为主，**无与微信同等级的服务端 query API**
- 分销 KYC **不建议首期依赖抖音**；若星选抖音版上线，可：
  1. 客户端 `tt.authenticateRealName` 成功
  2. 服务端记录「抖音侧已拉起认证」+ 用户自填姓名证号
  3. 叠加 **运营商三要素** 或 **人工复核**

**抖音小程序板块：** 若要做，仅 `tt.authenticateRealName`，并在运营台标记 `kyc_provider=douyin_client`，等级低于微信/支付宝 query 方案。

## 七、渠道与 KYC 矩阵（写死）

| 申请入口 | 可用 KYC | 禁止 |
|----------|----------|------|
| **星选微信小程序** | 微信（§3） | 支付宝、抖音 |
| **星选抖音小程序** | 抖音客户端认证（§6，可选） | 微信、支付宝 |
| **cs Web** | 微信内→微信；支付宝内→支付宝；其他→引导 | 同页混用三渠道 |
| **dr Web** | 同 cs | 同 cs |
| **fws 代创建分销员** | 可选短信+人工；或让分销员自行到 cs/dr/小程序完成 KYC 后绑定 | 不在 fws 内做 KYC |

## 八、数据模型扩展

```sql
distribution_kyc_records (
  id                uuid PK,
  subject_type      text,     -- affiliate_apply | salesperson
  subject_id        uuid NULL,
  openid            text NULL,
  alipay_user_id    text NULL,
  provider          text,     -- wechat_cityservice | wechat_face | alipay_certify | alipay_twometa | douyin_client
  real_name         text,
  cred_id_hash      text,
  cred_id_mask      text,
  out_seq_no        text UNIQUE,
  verify_id         text NULL,
  certify_id        text NULL,
  status            text,     -- pending | passed | failed
  verify_result     jsonb,
  verified_at       timestamptz,
  created_at        timestamptz
)

distribution_affiliate_applications (
  ...
  kyc_record_id     uuid REFERENCES distribution_kyc_records,
  kyc_verify_token  text NULL,  -- 仅传输用，不入库或短 TTL
  status            text        -- draft | kyc_pending | pending_ops | approved | rejected
)
```

## 九、运营管控台关联

| 功能 | 说明 |
|------|------|
| **个人分销员 · 待审核** | 展示 KYC  provider、脱敏证号、验证时间、`verify_result` 摘要 |
| **风控** | 同一 `cred_id_hash` 仅允许 1 个 active 分销员 |
| **审计** | 保留 `out_seq_no` / `certify_id` 180 天，不存证号明文 |
| **手动复核** | 微信/抖音 `V_OP_NA` 或支付宝失败时，运营可「线下核验」标记 |

**Ops 页面字段：**

- 实名渠道：微信 / 支付宝 / 抖音 / 人工
- 实名状态：已通过 / 失败 / 待补录
- 与 [分销体系实现设计](./分销体系实现设计-个人与服务商.md) 「个人分销员」审核队列联动

## 十、接入准备清单

| 平台 | 需申请能力 | 预估周期 |
|------|------------|----------|
| 微信小程序 | 城市服务实名校验 **或** 人脸核身 | 1～4 周（视资质） |
| 支付宝开放平台 | 身份验证 / 二要素 / 人脸核身产品签约 | 1～2 周 |
| 抖音 | 小程序实人能力（若做） | 不确定，首期可跳过 |
| 灵祺服务端 | 存储 KYC 记录、封装 API、小程序申请页 | 开发 1～2 周 |

**费用：** 微信/支付宝实名校验按次计费（具体以签约价为准），需在 `distributionPolicy.kycCostBearer` 配置为「平台承担」。

## 十一、推荐分期

| 阶段 | 范围 |
|------|------|
| **P0** | 小程序 **微信城市服务实名校验**（§3.1）+ 运营台展示 KYC 状态 |
| **P1** | cs/dr **支付宝实人 query**（§4.2）+ H5 环境检测自动选渠道 |
| **P2** | 微信 **人脸核身**（§3.2）升级 |
| **P3** | 抖音客户端认证（§6，视平台开放情况） |
