### 1.1 代码里已有的「类似物」（不能当提现用）

| 现有模块 | 实际用途 | 与分销提现关系 |
|----------|----------|----------------|
| `tenant_wallet_ledger` / `WalletPage` | **商家** ERP 账户余额（充值、抵扣订阅） | 对象不同，不可复用给分销员 |
| `PartnerAgentSettlementPage` | 总代看 **子代积分消耗** | 线下对账用，**不是现金分润** |
| `wechatPayV3.ts` + `meoo-wechat-pay-notify` | **收款**（Native/JSAPI 订阅） | 同一商户号可扩展 **付款**，但需另开产品与接口 |
| 冷启动 `payoutChannel: wechat_redpack` | PR 完单返现设计 | 仅 JSON 配置，**无 redpack API 代码** |

因此：**分销员提现要从 0 接入**，但可复用微信支付 V3 证书、运营台手工结算流程、现有 `merchant_payment_orders` 分润钩子设计。

## 二、合理接入原则（分期）

```
P0  只记账 + 运营台手工打款（无「提现」按钮）
P1  分销员「申请提现」+ 运营审核 + 手工标记已付
P2  服务商对公半自动（批次 + 导出 + 银行流水号）
P3  个人分销员微信/支付宝自动到账（需 KYC + 商户产品开通）
```

**不建议第一期就做自动提现**：商户号产品开通、场景报备、个税、失败重试成本高；与「分销员可不实名注册、提现前再 KYC」策略一致。

## 三、资金状态机（建议）

```
commission_ledger: pending → settleable(T+7) → locked(进入提现单) → paid
                                                      ↓
                                              failed / clawback
```

**分销员钱包（虚拟，非真实资金池）：**

```sql
distribution_wallets (
  owner_type     text,   -- individual_affiliate | partner_tenant
  owner_id       uuid,
  available_cents int,   -- 可提现
  frozen_cents    int,   -- 提现处理中
  withdrawn_cents int,   -- 累计已提
  updated_at     timestamptz
)

distribution_withdraw_requests (
  id              uuid PK,
  owner_type      text,
  owner_id        uuid,
  amount_cents    int,
  channel         text,  -- manual_bank | wechat | alipay
  payout_account  jsonb, -- 银行卡/支付宝账号/openid 等
  status          text,  -- pending_review | approved | paying | paid | rejected | failed
  kyc_record_id   uuid NULL,
  ops_reviewer_id uuid NULL,
  external_bill_no text NULL,  -- 微信 out_bill_no / 银行流水
  fail_reason     text NULL,
  created_at      timestamptz,
  paid_at         timestamptz NULL
)
```

## 四、按角色怎么「提现」

| 角色 | P0～P1（推荐首期） | P3（自动） |
|------|-------------------|------------|
| **服务商** | 运营台生成 **月度结算批次** → 财务 **对公转账** → 标记已付 | 仍建议对公，不走零钱 |
| **服务商分销员** | **平台不提现**；金额在结算单 **明细列示**，由服务商线下发 | 同左 |
| **个人分销员** | 推广页看「可提现余额」→ **申请提现** → 运营审核 → **手工打款**（银行/支付宝） | 微信 **商家转账** 到零钱（需 openid + KYC） |

## 五、灵祺 API 设计（分期）

### 5.0 已实现 · 运营台统一入口（注册表）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/meoo-ops-distribution-registry` | 佣金 / P1 提现 / P2 结算（`action` 字段） |
| POST | `/api/ops-sync/distribution-registry` | 同上（sync 别名） |

**`action` 一览（已实现）：**

| action | 用途 |
|--------|------|
| `patch_policy` | 全局策略（分润池、提现门槛等） |
| `patch_affiliate_commission` / `batch_patch_affiliate_commission` | 个人分销员佣金 **单个/批量** |
| `patch_partner_commission` / `batch_patch_partner_commission` | 服务商（代理商）佣金 **单个/批量** |
| `patch_salesperson_commission` / `batch_patch_salesperson_commission` | 服务商下分销员佣金 **单个/批量** |
| `withdraw_approve` / `withdraw_reject` / `withdraw_mark_paid` | P1 提现审核 |
| `settlement_batch_create` / `settlement_batch_confirm` / `settlement_batch_mark_paid` | P2 结算批次 |

读取：运营台 `GET` 注册表（`fetchRegistry`）中的 `distribution*` 字段；C 端 **`POST/GET /api/meoo-distribution-affiliate-apply`** 提交/查询个人推广员申请。

|------|------|------|

| POST | `/api/meoo-ops-distribution-settlement-batch` | 生成批次 |
| POST | `/api/meoo-ops-distribution-settlement-batch/:id/mark-paid` | 登记对公/手工已付 |

### P1 · 分销员申请 + 运营审核

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/meoo-distribution-wallet` | 可提现/冻结/已提 |
| POST | `/api/meoo-distribution-withdraw-request` | 申请提现 |
| GET | `/api/meoo-distribution-withdraw-requests` | 我的提现记录 |
| GET | `/api/meoo-ops-distribution-withdraw-requests` | 运营待审列表 |
| POST | `/api/meoo-ops-distribution-withdraw/:id/approve` | 通过 |
| POST | `/api/meoo-ops-distribution-withdraw/:id/reject` | 拒绝（解冻回 available） |
| POST | `/api/meoo-ops-distribution-withdraw/:id/mark-paid` | 手工确认已打款 |

**申请提现请求体（P1）：**

```json
{
  "amountCents": 4000,
  "channel": "manual_bank",
  "payoutAccount": {
    "bankName": "工商银行",
    "accountNo": "6222****",
    "accountName": "张三"
  }
}
```

**业务规则建议：**

| 规则 | 值 |
|------|-----|
| 最低提现 | ¥50（5000 分） |
| 单笔上限 | ¥5000 |
| 月累计上限 | ¥20000 |
| 首次 / 超 ¥200 | 必须 `kyc_status=passed` |
| 手续费 | 平台承担（不从分销员扣） |

### P3 · 微信自动提现（小程序个人分销员）

| 方法 | 路径 | 说明 |
|------|------|------|

## 六、外部支付接口（提现打款）

### 6.1 微信支付 · 商家转账（个人分销员，P3）

> 2025-01-15 起新版「商家转账」替代旧「商家转账到零钱」，需 **重新接入**。

| 项 | 内容 |
|----|------|
| 产品开通 | 商户平台 → 产品中心 → **商家转账** → 申请场景（如 **佣金报酬**） |
| 发起转账 | `POST /v3/fund-app/mch-transfer/transfer-bills` |
| 文档 | [产品介绍](https://pay.weixin.qq.com/doc/v3/merchant/4012711988) · [发起转账](https://pay.weixin.qq.com/doc/v3/merchant/4012716434) |
| 关键参数 | `appid`（星选小程序）、`openid`、`transfer_amount`（分）、`transfer_scene_id`、`out_bill_no` |
| 状态 | `WAIT_USER_CONFIRM` → 小程序拉起确认 → `SUCCESS` |
| 查询 | 商户单号查单（**仅 30 天内**） |

**与现有收款共用：** 同一 `WECHAT_PAY_MCH_ID`、APIv3 密钥、证书（`wechatPayV3.ts` 可扩展 `createTransferBill()`）。

**限制：**

- 需用户 **openid**（星选小程序登录已有）
- 需 **transfer_scene_id** 与场景报备字段
- 用户必须 **确认收款**（非静默到账）
- 单笔/单日额度见商户平台

### 6.2 支付宝 · 转账到支付宝账户（P3 备选）

| 项 | 内容 |
|----|------|
| 产品 | **单笔转账到支付宝账户**（需签约） |
| 文档 | [支付宝开放平台 · 转账](https://opendocs.alipay.com/open/009zou)（以签约页为准） |
| 适用 | dr Web / 支付宝内推广的个人分销员 |
| 与现有 | `alipayPay.ts` 为 **收款**，转账为另一套 API |

### 6.3 手工 / 对公（P0～P1，**首期默认**）

| 对象 | 方式 |
|------|------|
| 服务商 | 银行对公 + 发票 |
| 个人 | 运营导出 CSV → 网银/支付宝批量转账 → `mark-paid` |

**无需开通微信「商家转账」即可上线分销。**

### 6.4 不推荐首期

| 方式 | 原因 |
|------|------|
| 微信现金红包 | 营销属性，不适合佣金；冷启动文档里的 PR 返现也尚未接入 |
| 企业付款到零钱（旧） | 已升级，新商户走商家转账 |
| 灵活用工平台 API | 适合大规模劳务，接入周期长 |

## 七、与实名认证的关系（修正策略）

| 阶段 | 实名要求 |
|------|----------|
| 注册分销员 | **可不实名**（手机验证即可） |
| 累计待结算 < ¥200 | 只展示余额，不可提现或仅可申请 |
| **首次申请提现** | 必须 KYC（见 [分销员实名认证接口设计](./分销员实名认证接口设计.md)） |
| 微信自动提现 P3 | KYC + 绑定 openid（与微信实名信息一致更稳） |

**没有提现功能前，实名认证可以整段后置。**

| 周 | 内容 |
|----|------|
| 1～2 | `commission_ledger` + `distribution_wallets` 记账；仍无 C 端提现 |
